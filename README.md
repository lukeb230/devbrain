# DevBrain

A shared second brain for dev teams and their coding agents. Link a GitHub
repo and every Claude Code session on the team starts informed: who is
editing what right now, open PRs and collisions, the task board, team rules,
decisions, and what past sessions learned — and it reports back as it works.

**What's in the box**

- **Dashboard** (Next.js) — presence, PRs with merge traffic lights, tasks
  with spec ingest and Apple Reminders sync, session handoffs, lane claims,
  restore points, the team brain, AI PR reviews and standup digests.
- **Mac app** (Tauri) — a corner badge / menu-bar panel showing the live
  dashboard, native notifications, and the installer for everything below.
- **Claude Code plugin** — 15 MCP tools (`get_team_context`,
  `search_team_memory`, `who_is_editing`, tasks, claims, handoffs, decisions…)
  plus hooks for presence, collision checks, live context and session journals.
- **CLI** (`devbrain`) — zero-dependency installer/updater/doctor.
- **Agent tick** — server-side automation every 2 minutes (reviews, digests,
  journal summaries, memory index), with per-team AI budgets and alerts.

## Stack

Next.js 15 (app router) · Supabase (Postgres + Auth + Realtime, RLS
multi-tenant, pg_cron + pg_net) · GitHub App (webhooks + API) · Anthropic
API · Tauri 2 (macOS) · zero-dependency Node CLI and plugin.

## Deploy your own

### 1. Supabase
1. Create a project.
2. Apply **every** file in `supabase/migrations/` in filename order
   (`0001` … `0028`) — `supabase db push`, or paste each into the SQL
   editor. Four of them schedule purge jobs, so enable the `pg_cron`
   extension first (Database → Extensions).
3. Run `supabase/cron/agent-tick.sql` and `supabase/cron/watchdog.sql` once
   in the SQL editor (they embed the cron secret / deployment host, so they
   are not migrations).
4. Authentication → Providers → **GitHub** (a GitHub *OAuth app* for
   sign-in; the callback URL is shown in the Supabase UI). Set the Site URL
   and add `https://<host>/auth/callback` to the redirect URLs.

### 2. GitHub App (repo linking — separate from OAuth)
Settings → Developer settings → GitHub Apps → New:
- Setup URL `https://<host>/api/github/setup` (redirect on update);
  Webhook URL `https://<host>/api/github/webhook` with a secret.
- Permissions: Contents, Pull requests, Checks, Metadata — all read-only.
- Events: Push, Pull request, Pull request review, Installation,
  Installation repositories.
- Note the App ID, generate a private key, keep the slug.

### 3. Environment
Copy `.env.example` → `.env.local` and fill it in. Every variable the code
reads is listed there with a comment; the same set goes into Vercel.

### 4. Deploy
Push to GitHub → import in Vercel → set the env vars → point the GitHub
App's URLs at the production host. Then stamp the host into the clients
(`tools/set-server.sh https://<host>`) and commit — the CLI, the app and
the docs read it from there.

Local dev: `npm install && npm run dev` (http://localhost:3000); tunnel
webhooks with `ngrok http 3000`.

## Teams and access

Anyone with a GitHub account can sign in and create a team at `/welcome`.
Teams add people with invite links from **Settings → Members** (7-day
expiry, optional single-use). Roles: **owner** (team, roles, members) ·
**admin** (link/unlink repos, rules, writer app, Reminders mapping,
invites) · **member** (everything else). There is no allowlist.

Dev tokens (**Settings → Tokens**) connect machines; the Mac app mints its
own on first run. Tokens are sha256-hashed at rest and revoked when someone
leaves the team.

## Machines

Each Mac installs the app once (see `ONBOARDING.md`) and then keeps itself
on `main` without anyone doing anything:

```
git push main ─▶ ~/.devbrain/src (tarball of main)  ─▶ devbrain update reconciles:
                 plugin/  → claude plugin update          (new Claude sessions)
                 cli/     → wrapper + daily launchd updater
                 widget/  → CI builds the app → GitHub Release → staged swap
```

- `install.sh` — downloads the release, clears quarantine, installs and
  opens the app (`--cli` for the git + Node path; `beta` for the beta channel).
- `cli/bin/devbrain.mjs` — `setup` · `update` · `bootstrap` · `reminders` ·
  `doctor` · `ctx`. `bootstrap` exits 0/2/1 and prints a `DEVBRAIN_SUMMARY`
  line the app parses.
- `plugin/hooks/auto-update.mjs` — session-start trigger (throttled, detached).
- `.github/workflows/widget-release.yml` — builds both channels; **bump the
  version in `widget/src-tauri/tauri.conf.json` to publish**. The build is
  ad-hoc signed; `docs/NOTARIZE.md` is the checklist for a Developer ID.
- **Channels:** stable (`DevBrain.app`, `~/.devbrain`, `devbrain`, plugin
  `devbrain`) and beta (`DevBrain Beta.app`, `~/.devbrain-beta`,
  `devbrain-beta`, plugin `devbrain-beta` — `plugin-beta/` is generated by
  `tools/sync-beta-plugin.sh`). Both default to the same server; a beta
  server can be baked in with `DEVBRAIN_BETA_SITE` at build time.
- Headless (CI, Cowork): set `DEVBRAIN_URL` + `DEVBRAIN_TOKEN`; the hooks and
  MCP server use them when no config file exists.

## Server automation

`/api/agents/tick` runs every 2 minutes from `pg_cron`: PR review,
auto-complete matching, spec analysis, task footprints, merge traffic
lights, zombie branches, session journals, the team-memory index, and the
daily digest. Teams are served round-robin; each team has a daily AI call
cap (`orgs.ai_daily_cap`, default 300) shown on **Settings → Team**.
`DEVBRAIN_TICK_DISABLED` switches units off without a deploy.

Alerts: failures open deduplicated alerts (`alert_log`) delivered in-app to
owners/admins and, optionally, to a Slack/Discord webhook per team
(**Settings → Team**) or the operator (`DEVBRAIN_OPS_WEBHOOK`). The
Postgres watchdog (`supabase/cron/watchdog.sql`) reports a dead tick from
outside Vercel. `devbrain doctor` and `/api/v1/health` show the state.

## Restore points (from any deploy script)

```bash
curl -sS -X POST "$DEVBRAIN_URL/api/v1/restore-points" \
  -H "Authorization: Bearer $DEVBRAIN_TOKEN" -H "Content-Type: application/json" \
  -d "{\"repo\":\"owner/name\",\"sha\":\"$(git rev-parse HEAD)\",\"tag\":\"$TAG\",\"bundle_hash\":\"$HASH\"}"
```

## Security model

- Webhooks: HMAC signature verification; service-role writes.
- Machines: per-user bearer tokens, sha256-hashed, revocable; desktop
  sign-in uses one-time device tokens and a browser hand-off.
- Browser: Supabase Auth (GitHub OAuth); RLS scopes every read to the
  member's teams; server actions check roles.
- Hook payloads carry file *paths* and redacted transcript excerpts — never
  file contents. No cloud or infra credentials touch this app.
