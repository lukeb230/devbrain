## 0. Orientation

**What DevBrain is.** A shared awareness layer for repositories where work happens through coding agents. It carries what the team is doing — who is editing what, what is claimed, what merged, what was decided — into the agent's own context, and acts on it *before* the agent writes. Three claims make the position: it runs **inside the agent's loop** (a PreToolUse hook can stop an edit), it **spans agents** (Claude Code, Cursor, Codex report into one picture), and it **accumulates** (journals, decisions, handoffs outlive any transcript). Any one is copyable; all three together is the pitch.

**Surfaces.**
- **Menu-bar panel** (440 px Tauri webview, `/widget`) — glanceable presence, needs-you, tasks.
- **Console** (full window in the same Tauri app, `/desk/*`) — Home, Board, Pull requests, Rules, Members/Tokens/Team, Specs, Brain, Feed & memory, History, Reminders, This Mac, ⌘K jump. Formerly "Desk"; the browser dashboard was retired on 2026-09-07 and old URLs land on `/open`.
- **CLI + agent plugin** (`devbrain`, zero-dependency Node, bundled Node inside the app) — hooks at SessionStart, PreToolUse, PostToolUse, UserPromptSubmit, SessionEnd; installed by one click ("Set up this Mac") for Claude Code, Cursor and Codex.
- **MCP server** — 15 tools: `get_team_context`, `who_is_editing`, `claim_area`, `release_claim`, `list_tasks`, `add_task`, `start_task`, `complete_task`, `leave_handoff`, `pickup_handoff`, `broadcast`, `log_decision`, `search_team_memory`, `get_brain`, `update_status`.
- **Website** — landing, `/how-it-works`, `/pricing`, `/privacy`, `/terms`, built inside the Next app.

**Stack.** Next.js 15 App Router on Vercel (Fluid compute); Supabase Postgres with RLS, `pg_cron`, `pg_net`, service-role RPCs; Tauri 2 macOS app (`widget/src-tauri`); vitest for the pure libraries (367 tests, no DB/network by design); Stripe in test mode; Anthropic Messages API for reviews/journals/digests.

**The two repos.** `~/Downloads/devbrain` is the **frozen FlowSync** deployment (`/Applications/DevBrain.app`, `~/.devbrain`) and must never be touched. `~/Downloads/devbrain-product` is the product (`/Applications/DevBrain Beta.app`, `~/.devbrain-beta`, `devbrain-beta://`). Both plugins are enabled in `~/.claude/settings.json`; the sandbox harness isolates per-agent `CLAUDE_CONFIG_DIR` and `DEVBRAIN_HOME` for exactly this reason.

**The agent tick.** `pg_cron` POSTs `/api/agents/tick` every 2 minutes. Each tick does bounded work with cross-team fairness: one PR review, one auto-complete match, one spec analysis, one zombie branch, one journal summary, plus deterministic units every tick (traffic lights, merge order, branch sync, memory index, task footprints), a standup digest once per repo per day, Stripe overage reporting hourly, and housekeeping. **Every AI-bearing unit is globally serialised at one item per tick** — ~720 reviews/day and ~720 journals/day for the whole platform, regardless of team count.

## 3. The true liveness picture

The product describes itself as live. Here is what actually happens, per kind of state, and the realistic delay.

### The transport, once
- **Menu-bar panel**: subscribes to Supabase Realtime `postgres_changes` on 11 tables (`prs, branches, activity, sessions, events, tasks, handoffs, claims, linked_repos, pr_reviews, digests`) and calls `router.refresh()` debounced 300 ms; plus a **20 s poll** while visible and a refresh on visibility change (`src/app/widget/live.tsx`). → A DB write reaches the panel in **~0.3–1.5 s** (realtime), worst case 20 s.
- **Console**: **no realtime subscription at all.** It re-renders on navigation and after server actions; the onboarding wall polls every 5 s only while a request is pending or the editor check is open. → The Console is **as stale as your last click**.
- **Native notifications**: the Mac app subscribes to `alert_log` and `prs` inserts/updates (`notifier.tsx`) → **~1 s**.
- **The agent's own awareness**: the SessionStart hook injects a full team brief once; the **UserPromptSubmit** hook (`live-context.mjs`) fetches context on every prompt and injects only the diff. → An agent learns about teammates **at its next prompt, never mid-turn**. Cursor's `beforeSubmitPrompt` cannot add context, so **Cursor agents get the brief at session start only**.

### Per kind of state
| State | How it gets to the server | How it reaches a teammate's screen | Realistic delay |
|---|---|---|---|
| **Presence** (who is working, on what branch) | `SessionStart` posts `session_start`; `PostToolUse` posts `activity` per file-changing tool call; a heartbeat on prompts; `SessionEnd` posts `session_end`. A session counts as active for **15 min** after `last_seen` (`ACTIVE_WINDOW_MIN = 15`). | Panel: realtime on `sessions`/`activity`. Console: next navigation. | **Appears** within ~1–2 s of the first edit. **Disappears** immediately on a clean SessionEnd, otherwise **up to 15 min** after the last edit. A crashed session lingers 15 min. |
| **Collisions** (about to edit a file a teammate is on) | Not stored. The **actor's** PreToolUse hook fetches `/api/v1/context` synchronously per edit (3 s timeout, fail-open) and compares the file to teammates' active-session `files` and open `claims`. | To the actor: **at the moment of the edit** — the decision is live. To *others*: the "collisions" list in Needs-you is computed at render from the same rows. | The check sees anything a teammate's PostToolUse has already posted — typically **seconds** behind their last edit. If DevBrain is unreachable the guard **fails open** in ≤3 s and says nothing. |
| **Claims / handoffs / broadcasts / decisions** | MCP tool → API → row, immediately. | Panel realtime; Console on navigation; other agents at their next prompt. | **~1 s** to the panel; **next prompt** to an agent. |
| **PR status** (open/merged/head_sha) | GitHub webhook → `prs` row, on arrival. | Panel realtime on `prs`; native notification. | **Seconds** after the GitHub event. |
| **Traffic lights, merge order, rebase flags** | Computed by the **tick every 2 min** (deterministic unit), not on the webhook. | Panel realtime on the tick's writes. | **Up to 2 min** after the underlying change. |
| **AI PR review** | Tick: **one unreviewed PR per tick, platform-wide**, with cross-team fairness. | Panel realtime on `pr_reviews`. | **2 min × (number of unreviewed PRs ahead of yours across all teams)**. With three PRs opened at once, the last was reviewed ~8 min later; a silent tick skip on Sep 12 stretched that. |
| **Tasks** (add/start/complete) | MCP tool or Console action → row. | Panel realtime on `tasks`; Console on navigation. | **~1 s** panel. |
| **Task auto-complete from a merged PR** | Tick: one merged, unlabeled PR per tick. | Same. | **Up to 2 min** after merge, more if queued. |
| **Task footprints** (predicted lanes) | Tick, batched. | Same. | Minutes. |
| **Journals** | `SessionEnd` → a detached child POSTs the redacted excerpt to `journal_queue` → tick summarises **one per tick, platform-wide**. | Panel realtime on `journals`/memory. | **2 min × queue depth.** Three agents ending together: 23:10, 23:12, 23:14. |
| **Standup digest** | Tick, once per repo per day after 13:00 UTC. | Injected into the next SessionStart brief. | Daily. |

**Plain summary.** The panel is genuinely live (~1 s) for anything that is a database write. The Console is not live. An agent's awareness is per-prompt. Everything the tick computes — lights, merge order, reviews, journals, auto-complete — is **up to 2 minutes behind**, and the AI-bearing units are **globally serialised at one item per 2 minutes**, which is a hard ceiling of ~720 per day per unit type for the entire platform at the current cron cadence. At the 150-team beta cap, five sessions per team per day already exceeds journal capacity.

## 5. Supporting a second agent platform

**Two are already shipped.** Cursor and Codex have run real sessions (9 and 2). The per-host surface is small and concentrated:

- `plugin/hooks/host.mjs` (~150 lines): `detectHost` (argv flag, env, or payload sniffing — Cursor payloads carry `cursor_version`), `readInput`, `editedFile`/`isEditTool` (which tool names count as edits per host), `emitContext` (Cursor wants `{additional_context}`), `emitGuard` (below), prompt-stamp dedupe.
- `cli/bin/hosts.mjs` (~200 lines): writes and strips each host's config — Cursor `~/.cursor/hooks.json` + `mcp.json`; Codex `~/.codex/config.toml` (`[mcp_servers.<id>]`, `[features] hooks = true`) + `hooks.json` (Claude-shaped); an `AGENTS.md` block.
- Everything else — the five hook scripts, the MCP server with all 15 tools, the server — is host-agnostic.

**What each host can and cannot do today**
| Capability | Claude Code | Codex CLI | Cursor |
|---|---|---|---|
| Presence, activity, journals | ✓ | ✓ | ✓ |
| Team brief at session start | ✓ | ✓ | ✓ |
| Per-prompt context diff (the "pulse") | ✓ | ✓ | ✗ — `beforeSubmitPrompt` can allow/deny but cannot add context |
| Collision guard | `ask` — the person chooses | `ask` | **deny only**, made sticky: the file denial persists up to an hour until the person replies, then allows silently (`emitGuard`) |
| MCP tools | ✓ | ✓ | ✓ (no `${workspaceFolder}`; the server finds the workspace itself) |

**Gemini CLI: not supported, not referenced anywhere in the codebase.** An estimate, with the caveat that Gemini CLI's hook surface needs a current check:
- **Ports cheaply (≈1 day):** the MCP server — if Gemini CLI speaks MCP, all 15 tools and `get_team_context` work by adding a config writer to `hosts.mjs`. That alone gives an agent the brief on request, claims, tasks, memory.
- **Needs real work (days to a couple of weeks):** presence, the collision guard and journals all depend on lifecycle hooks (session start/end, before/after tool). If Gemini CLI exposes equivalents, it is another `host.mjs` branch plus payload normalisation — the Cursor port took **four commits over two days** to get dedupe, heartbeat and the deny semantics right, and that is the realistic shape. If it exposes no hooks, presence and the guard would need a wrapper process or a polling MCP resource, which is a different and weaker product on that host (no interruption before the write).
- **Windows/Linux** is a separate axis: the CLI and plugin are plain Node and already portable; the app (panel, Console, one-click setup, notifications) is macOS-only. That is the bigger gap for a mixed team than any single agent host.

## 6. Underrated, half-built, abandoned — and what is hard to copy

### Underrated (working, under-used)
- **The sandbox harness** (`~/dev/faketeam`, not in the repo): three autonomous Claude Code agents with personas, isolated homes, budgets and a watchdog, running against a real repo. It produced 30 journals, 28 AI reviews, 26 PRs and a correct guard firing for about $1 a cycle. It is simultaneously the integration test, the demo generator and the only source of "usage". Nobody else will have this on day one.
- **The per-prompt pulse** (`live-context.mjs`): diffs the team context on every prompt and injects only what changed. This is the actual "in the loop" mechanism; the landing page barely mentions it.
- **Spawned sessions as teammates** (`devbrain spawn`, child tokens): a solo developer's parallel agents collide with each other and the product treats them as a team. Shipped Aug 30; one real use (`Nova · 2`).
- **`search_team_memory`** over 103 indexed rows across journals, reviews, tasks, decisions — the accumulate claim, and the thing that gets better with use.
- **Derived state everywhere**: lights, merge order, onboarding steps — computed from rows, never stored. It is why the Console can be stale without ever being *wrong*.

### Half-built / built but unused
- **Specs** (upload a document → the tick extracts requirements → tasks): the `spec_ready` path fired once; `specs` is empty now.
- **Restore points / revert-from-History as a PR**: built behind a write switch; 0 rows.
- **Reminders sync** (macOS Reminders lists ↔ tasks): built, CLI `reminders add/remove`; 0 mappings.
- **Brain graph + `generate-brain` skill**: 9 brain notes indexed; the graph renders; adoption depends on repos having `.brain/`.
- **Handoffs**: 1 written, 0 picked up.
- **`leads`** with no outbound email: the form works; nothing can reply.

### Abandoned or parked
- **Phase 4 autonomy** (agents running without Luke prompting each session) — shelved; interactive multi-session only.
- **The browser dashboard** — retired to `/open` on Sep 7; `src/app/dashboard/*` actions remain as the server-action layer the Console reuses.
- **Fifteen merged `fix/*` / `feat/*` branches** still exist locally; `ui-experiments` is fully merged. Cleanup only.
- **Website redesign explorations** (five directions requested twice; four of five v4 files written in a scratchpad; none adopted). The live site is the "five beats" version.

### What would be genuinely hard to copy
Honest answer: nothing here is a deep moat on its own; the difficulty is in the accumulation of host-specific plumbing and the behaviours that only show up under real multi-agent load.
1. **The guard inside the tool loop, across three hosts.** A synchronous server round-trip with a 3 s fail-open budget on every file-changing tool call, with the Cursor adaptation (deny, sticky for an hour, released by the person's next reply) — that is knowledge of each host's hook semantics that took real iteration, and a competitor bound to one vendor's hooks cannot cover the teammate on another tool.
2. **Teammate = token label, not account.** Humans, spawned sessions and headless agents are the same thing to everyone else. It is a small design decision with large consequences (the sandbox, `spawn`, headless CI all fall out of it).
3. **The tick's economics**: cross-team fairness, per-team daily AI caps, a circuit breaker, refunds for unanswered calls, overage accounting to Stripe — the operational layer for selling AI-backed features to many small teams without one busy team starving the rest.
4. **Tenant isolation that was actually attacked**: installation-hijack guard, requester-matched claims, SSRF allowlists, a cross-tenant leak test. Table stakes, but done.
5. **Derived state as a discipline** — the thing that makes the product robust to its own staleness.

What is *not* a moat: the AI review (a false positive on a comparator is already on record), the Console UI, and the memory search — all reproducible.
